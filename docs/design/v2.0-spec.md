### Replay validation (real corpus, 2026-07-05)

Ran `replay` over the live 153,637-entry audit log. **107,365 evaluated, 46,272 skipped (truncated), 0 other.**

- **14 newly-allowed, all intentional P1 fixes** (13× `eval "$(fleetops …)"`, 1× local `… | python3 -m json.tool`). **Zero dangerous commands newly allowed** — the P1 relaxation is surgically correct.
- **24 newly-blocked, all P2 self-protection** on `Write`/`Edit` to `.claude/settings*.json`.

Two findings this surfaced, both feeding the roadmap:
1. **Self-protection vs. legit config edits.** Those 24 blocks are real historical edits to `settings.json`. Hard-blocking all of them breaks Lee's own config work → **allow-once escape hatch + content-aware self-protection** is the top next phase (block only edits that touch the guardrail hook stanza; allow the rest).
2. **Truncation blinds replay (30%).** v1 logs a 100-char truncated command, so replay can't re-evaluate long commands → **audit-log v2 must record the full command** for replay to be a trustworthy CI gate.

**Remaining (DCG nice-to-haves, not yet built):** allow-once HMAC codes · `test`/`explain`/`doctor`/`replay` CLI subcommands · audit-log rotation · pack-as-YAML custom packs · Aho-Corasick pre-filter · context-aware relaxation (rebase-recovery). None block the P1/P2/P4 wins from shipping. Not committed (per "commit only when asked" + difflabai gating).

## 1. Why v2

v1 is a well-architected Rust hook (tree-sitter AST, wrapper unwrapping, fail-closed core, ~5.7k LOC) and it works — **152,272 decisions / 903 blocks over ~4.5 months** on `roadrunnerM5`. The architecture is not the problem. Four things are:

| # | Problem (evidence from live audit) | Severity |
|---|---|---|
| **P1** | **False positives on the fleet's own protocol.** `eval "$(fleetops session-stamp cic)"` blocked as "code injection" (75×); `fleetops state show \| python3 -c ...` blocked as "pipe to interpreter" (311× — the single largest block class). These are required wake rituals, not attacks. When a guardrail cries wolf on legit work, agents learn to route around it and it stops protecting. | **Highest** |
| **P2** | **The guard doesn't guard itself.** `protected_patterns` covers `.env`/`.ssh`/`.pem` but not `~/.claude/settings.json` (where the hook is registered) or the guardrails binary/config dir. In YOLO mode an agent can Edit the hook out or overwrite the binary. `GUARDRAILS_DISABLED=1` is a documented total bypass. | **High** |
| **P3** | **No introspection or tuning surface + maintenance drift.** No `test`/`explain`/`replay`. I had to hand-grep 152k JSONL lines to assess it. Uncommitted work sits since February; deployed binary is stale; no release since v0.1.0; audit log unbounded at 39.5 MB with no rotation. | **Medium** |
| **P4** | **Thin secret coverage at the edges.** Misses `sk-ant-…`, `sk-proj-…`/`sk-…`, `xox[baprs]-…`, `sk_live_…`, inline PEM blocks in Write content. | **Medium** |

v2.0's job: **kill the false positives without weakening the catastrophic core, close the self-protection hole, and make the thing tunable and observable** — borrowing the proven mechanisms DCG already ships for exactly these problems.

## 2. DCG concept mining — adopt / adapt / reject

DCG is the same problem solved one maturity-tier up (Rust, 50+ opt-in packs, context classification, allow-once codes, scan mode, 8 agent protocols). Not everything transfers — Lee's fleet is single-machine, all-Claude-Code, and touches maybe 6 of DCG's 50 domains. Take the *mechanisms*, not the bulk.

| DCG concept | Decision | Maps to | Rationale |
|---|---|---|---|
| **SpanKind context classification** (Executed / InlineCode / Data / Comment / Unknown) | **ADOPT — flagship** | P1 | The direct cure for P1. `grep "git reset --hard"` is Data → allow; bare `git reset --hard` is Executed → block. We already have the tree-sitter AST that yields node kinds; we're just not using it to classify *context*. Highest leverage single change in v2. |
| **Modular opt-in pack system** (namespaced, keyword-declared, TOML-enabled, custom YAML) | **ADOPT (subset)** | P1, extensibility | Turns the monolithic 50-rule `dangerous.rs` into composable, per-project-configurable units. Ship only the packs the fleet uses (`core.*`, `system.disk`, `database.sqlite/postgres`, `containers.docker`, `secrets.*`). Don't port Kafka/PagerDuty/Braintree. |
| **Safe-patterns-first with negative lookahead** | **ADOPT** | P1 | `git push --force(?![-a-z])` blocks force but allows `--force-with-lease`; `restore (?!--staged)` allows staged restores. The granular whitelist layer v1 lacks. Requires `fancy_regex` for the ~15% of patterns needing lookahead. |
| **Aho-Corasick keyword pre-filter** | **ADAPT** | structure, perf | Each pack declares keywords; a single Aho-Corasick automaton over all enabled packs eliminates 95%+ of rule evaluation in O(n). Perf isn't our pain, but this *is* the clean structural gate that makes packs cheap and gives the fast-path an explicit home. |
| **`explain` / `test` / `doctor` CLI** | **ADOPT** | P3 | Introspection is what I was missing during the assessment. `guardrails test "<cmd>"`, `guardrails explain "<cmd>"` (decision trace + timing), `guardrails doctor` (hook-integrity check → also serves P2). |
| **Audit replay / decision trace** | **ADOPT (extend)** | P3 | DCG has per-decision explain; we add **`guardrails replay <audit.jsonl>`** — re-run a proposed ruleset over the historical corpus and diff allow/deny. This is how we prove a P1 fix newly-allows nothing dangerous *before* enforcing. Our 152k-line log is a rare regression oracle; build the tool that uses it. |
| **Allow-once short codes** (HMAC-SHA256, 24h / single-use) | **ADOPT** | P1, escape-hatch | Sanctioned emergency override without a permanent allowlist edit. Removes the incentive to disable the whole guard when one command is wrongly blocked. Use HMAC keyed on `GUARDRAILS_ALLOW_ONCE_SECRET`. |
| **Context-aware relaxation** (rebase-recovery mode) | **ADOPT (generalize)** | P1 | DCG detects `.git/rebase-merge/` and relaxes `checkout -- .`. Generalize the principle: *a command dangerous in state A is routine in state B; detect state, scope the rule.* First instances: rebase-recovery, and `rm -rf` inside a scratch/worktree dir. |
| **Dual output streams** (JSON→stdout, human→stderr) + suggestion system + schema-versioned output | **ADOPT** | agent ergonomics, P3 | Agents parse stdout, humans read stderr; every block carries a remediation tip ("use `git stash` first"). `schema_version` on output for forward-compatible tooling. |
| **Hierarchical config** (env > `DCG_CONFIG` > project `.dcg.toml` > user > system > compiled) with additive merge | **ADOPT** | P1, per-project | Per-project `.guardrails.toml` lets the servitor repos declare their known-good idioms locally instead of one global allowlist fighting every context. |
| **Scan mode** (`scan --staged`, pre-commit, SARIF/markdown/JSON) | **DEFER (v2.1)** | commit-time safety | Extends the guard from runtime to commit-time (Dockerfile RUN, CI `run:`, Makefile recipes). Valuable but orthogonal to the four problems; sequence after core v2.0. |
| **Multi-agent hook protocols** (Codex, Gemini, Cursor, Grok, …) | **DEFER (Codex only)** | fleet reach | Fleet is all Claude Code; Codex is in the peer-review loop. Add Codex payload parsing when convenient; skip the other 6. |
| **Fail-OPEN default** | **REJECT (hybrid instead)** | philosophy | DCG defaults fail-open (allow on parse error/timeout). For YOLO-mode safety that's backwards for the catastrophic core. v2 keeps **fail-closed on `core.*` + `system.disk`**, fail-open on opt-in advisory packs, with a global 200ms deadline. Deliberate split, not a blanket. |
| **Edition 2024 / nightly toolchain** | **REJECT** | portability | DCG requires nightly. v1 is stable Rust and installs as a single static binary. Keep stable; don't take a nightly dependency for features we can get on stable. |
| **50+ cloud/SaaS packs** | **REJECT (bulk)** | scope | The fleet doesn't touch Kafka/NATS/PagerDuty/Braintree/Algolia/etc. Adopt the pack *architecture*; ship ~6 packs. Bloat is a cost, not a feature. |
| **Performance budget system** (per-stage tiers + global timeout) | **ADOPT (lightweight)** | robustness | A single global 200ms deadline with fail-open-on-timeout for advisory packs (fail-closed core still blocks). Skip DCG's elaborate per-tier budget accounting. |

## 3. v2.0 architecture

Evaluation pipeline (extends v1's; new/changed stages **bold**):

```
stdin JSON (Claude Code PreToolUse; +Codex later)
  │
  1. Parse & identify tool (Bash / Read / Edit / Write / Unknown)
  │
  2. Self-protection pre-check ─────────────► DENY   [P2] bold
  │    Edit/Write targeting the hook registration,
  │    guardrails binary/config/allowlist, or settings.json
  │
  3. Disabled/bypass check (logged, HMAC-gated) [P2] bold
  │
  4. Command normalization (strip binary paths, unwrap sudo/timeout/env/…)
  │
  5. AST parse (tree-sitter-bash) → CommandAnalysis
  │    └─ dynamic-command / pipe-to-shell / env-hijack  (v1, retained)
  │
  6. SPAN CLASSIFICATION (SpanKind) ──────────────────────── bold  [P1]
  │    label every token: Executed | InlineCode | Data | Comment | Unknown
  │    only Executed + InlineCode proceed to rule matching
  │
  7. Aho-Corasick keyword pre-filter over enabled packs ──── bold
  │    no keyword hit → fast-path ALLOW
  │
  8. SAFE-PATTERNS first (negative-lookahead whitelist) ──── bold  [P1]
  │    match → ALLOW (e.g. --force-with-lease, restore --staged, scratch rm)
  │
  9. Pack rule matching (core.* fail-closed; advisory fail-open)
  │    match → DENY (+ suggestion, + allow-once code)
  │
 10. Heredoc / inline-code deep scan (Data-context escalation)  [later]
  │
 11. Audit log (JSONL, schema-versioned, rotated) + dual output
  │    clean → ALLOW
```

**Retained from v1 unchanged:** tree-sitter AST core, wrapper unwrapping, secrets/exfiltration detection (extended per P4), file protected-patterns, three-safety-level model (critical/high/strict).

## 4. Key subsystems

### 4.1 SpanKind context classification (P1 — the flagship)

The AST already parses commands into nodes. Classify each token's span:

- **Executed** — command word, unquoted args → checked
- **InlineCode** — body of `-c`/`-e` flags (`python -c "…"`, `bash -c "…"`) → checked (and escalated to heredoc/inline deep scan)
- **Data** — single-quoted strings, heredoc bodies, `grep`/`echo`/`rg` pattern args → **not** matched against exec rules
- **Comment** — `#`-prefixed → skipped
- **Unknown** — conservative: treat as Executed

Cures the top-2 FP classes directly:
- `fleetops state show | python3 -c "import json,sys; …"` — the `python -c` body is InlineCode; it parses JSON, contains no destructive call → **allow**. (The rule that blocks it today, "pipe to interpreter," is retired in favor of classifying *what* is piped: remote-content→interpreter stays blocked, local-structured-data→interpreter allowed.)
- `eval "$(fleetops session-stamp cic)"` — see 4.2.

### 4.2 The `eval "$(...)"` case — trusted-command carve-out

`eval "$(cmd …)"` is genuinely dynamic (v1 correctly flags the *shape*), but the danger is *what `cmd` is*. `fleetops session-stamp`, `fleetops`, `direnv hook`, `brew shellenv`, `pyenv init` are known-safe generators. v2 resolves the inner command substitution via AST and checks its command word against a **trusted-generator allowlist** (config-driven, per-project extensible). Trusted generator → allow; unknown generator inside `eval "$(...)"` → keep blocking. This is safe-patterns-first (stage 8) applied to the dynamic-command rule.

### 4.3 Self-protection (P2)

New stage-2 rule set, fail-closed, non-disableable, matched *before* normalization so it can't be unwrapped around:

- **Deny Edit/Write** to: `~/.claude/settings.json`, `~/.claude/settings.local.json`, any `.claude/settings*.json`, the guardrails install dir (`~/.claude/guardrails/**` incl. binary, `config.toml`, `allow.toml`), and this repo's `src/**` when installed-mode.
- **Deny Bash** that rewrites the same (`>`, `tee`, `sed -i`, `mv`, `cp`, `install`, `ln -sf` onto those paths; `chmod -x` the binary).
- **`GUARDRAILS_DISABLED` / `GUARDRAILS_WARN_ONLY`**: still honored (operator escape hatch) but (a) require the HMAC allow-once secret to be set, (b) logged at WARN with the full command, (c) surfaced by `guardrails doctor` if left on. Document the threat model explicitly: the guard protects against an agent *in* a session, not an operator with shell access — an `export` in a shell profile defeats it by design, and that's the human's call.

### 4.4 Pack system

```yaml
# ~/.claude/guardrails/packs/core.git.yaml
name: core.git
description: Git operations that destroy uncommitted or unpushed work
always_on: true          # cannot be disabled
fail_closed: true
keywords: ["git", "reset", "push", "branch", "clean", "stash", "restore", "checkout"]
safe_patterns:
  - id: force-with-lease
    pattern: 'git\s+push\b[^|;&]*--force-with-lease'
  - id: restore-staged
    pattern: 'git\s+restore\s+(--staged|-S)\b'
rules:
  - id: git-reset-hard
    pattern: 'git\s+reset\s+--hard'
    message: "git reset --hard destroys uncommitted changes"
    suggestion: "Use 'git stash' first to save your changes."
    severity: error
  - id: git-push-force
    pattern: 'git\s+push\b[^|;&]*--force(?![-a-z])'
    message: "Force-push can overwrite remote history"
    suggestion: "Use '--force-with-lease' instead."
```

- **Namespaces**: `core.*` (always-on, fail-closed), `system.*` (default-on), `database.*` / `containers.*` / `secrets.*` (opt-in), `fleet.*` (Lee-specific: trusted generators, scratch-dir rms, worktree awareness).
- **Enable/disable**: `[packs] enabled/disabled` in TOML; per-project `.guardrails.toml`; `GUARDRAILS_PACKS` / `GUARDRAILS_DISABLE` env.
- **Validation**: `guardrails pack validate <file>` — compile every regex, reject catastrophic-backtracking patterns, warn on missing keywords.
- **Ship set for v2.0**: `core.filesystem`, `core.git`, `system.disk`, `secrets` (P4-extended), `containers.docker`, `database.sqlite`, `fleet.trusted-generators`. That's it. Add on demand.

### 4.5 Allow-once codes (P1 escape hatch)

On a block, emit a 6-digit code = `HMAC-SHA256(secret, normalized_command)[:6]` (falls back to plain SHA256 if `GUARDRAILS_ALLOW_ONCE_SECRET` unset). `guardrails allow-once <code>` writes a single-use, 24h-TTL permit keyed to that exact command. Next invocation consumes it. Gives a wrongly-blocked agent a sanctioned path instead of "disable the whole thing."

### 4.6 Introspection & tuning (P3)

- `guardrails test "<cmd>"` — evaluate, don't execute (pretty/json).
- `guardrails explain "<cmd>"` — full decision trace: normalization → spans → pre-filter → safe-patterns → matched rule, with per-stage timing.
- `guardrails replay <audit.jsonl> [--ruleset <dir>]` — **re-run current-or-proposed rules over the historical corpus; output the allow→deny and deny→allow diff.** The regression oracle for every future rule change.
- `guardrails doctor` — hook still registered? binary matches installed hash? disable-flags set? log rotating? self-protection intact?
- `guardrails packs [--verbose]`, `guardrails config` — show effective config with winning-layer provenance (ties into the fleet's config-canon guardrail: announce resolved values + source).

### 4.7 Audit & robustness (P3)

- **Log rotation**: size-based (e.g. 25 MB → `audit.jsonl.1`, keep N), or daily. Configurable. Non-negotiable for v2.
- **Schema-versioned JSONL**: `schema_version`, plus `matched_span` / `matched_text_preview` / `pack_id` / `rule_id` on denies for `replay` to consume.
- **Global 200ms deadline**: exceed → fail-open on advisory packs, fail-closed core already resolved by then (core is O(n) pre-filter + a handful of patterns).

### 4.8 Secret coverage (P4)

Add to `common.rs` / `secrets` pack: `sk-ant-[A-Za-z0-9_-]{20,}` (Anthropic), `sk-proj-[A-Za-z0-9_-]{20,}` and `sk-[A-Za-z0-9]{20,}` (OpenAI), `xox[baprs]-[A-Za-z0-9-]{10,}` (Slack), `sk_live_[0-9a-zA-Z]{24,}` / `rk_live_…` (Stripe), and `-----BEGIN (RSA |EC |OPENSSH |)PRIVATE KEY-----` in Write content. Keep the existing AWS/GitHub/generic patterns.

## 6. Migration path (v1 → v2)

1. **Extract rules → packs.** Mechanical: the 50 `dangerous.rs` rules become `core.*` / `system.*` YAML packs. Behavior-preserving; `replay` must show zero deny→allow drift on the corpus.
2. **Land SpanKind + safe-patterns + trusted-generator carve-out.** `replay` should show the P1 blocks (eval/python-c) flip deny→allow, and *no* new allows on anything in the destructive set.
3. **Land self-protection + secret extensions.** `replay` shows new denies only on hook/settings/secret targets.
4. **Land introspection CLI + log rotation.** No behavior change.
5. **Cut v0.2.0**, rebuild, redeploy, update `install.sh`.

Every step gated on a green `replay` diff against the 152k-line corpus. That's the acceptance test.
